# Android release checklist

## Identity and build
- [ ] Confirm application ID/package name and display name.
- [ ] Confirm `version:` and build number in `pubspec.yaml`.
- [ ] Confirm min/target SDK and plugin compatibility.
- [ ] Check app icon, adaptive icon, splash screen and orientation.
- [ ] Check permissions; remove any permission not needed by the app.
- [ ] Test on a small phone and a current Android device.

## Security and data
- [ ] Keep API secrets and signing credentials out of source control.
- [ ] Add only non-secret placeholders to `.env.example`.
- [ ] Review local data retention, export and deletion behavior.
- [ ] Review network security, backend rules and authentication paths if used.
- [ ] Test no-network, timeout, denied-permission and expired-session flows.

## Firebase and AdMob (only if enabled)
- [ ] Confirm the owner supplied real project configuration and selected services.
- [ ] Verify Android app ID/package matches the intended Firebase/AdMob app.
- [ ] Use official test ad units during development.
- [ ] Verify consent/privacy requirements for the actual audience and regions.
- [ ] Never commit production secrets or pretend an integration is complete without validation.

## Play Store
- [ ] Verify privacy policy URL and Data safety answers.
- [ ] Verify content rating, target audience and ads declaration.
- [ ] Prepare screenshots, feature graphic, app description and release notes.
- [ ] Review accessibility and crashes on a real device.
- [ ] Build and inspect a release AAB.
- [ ] Test internal track before production rollout.
- [ ] Keep a record of build number, commit, test results and known issues.

## Commands (run from the Flutter project root)
```bash
flutter pub get
dart format --set-exit-if-changed .
flutter analyze
flutter test
flutter build apk --debug
# After signing and release configuration are verified:
flutter build appbundle --release
```

Apps created with `scripts/create_app.py` have Android product flavors. Select
the intended flavor and matching Dart environment explicitly, for example:

```bash
flutter build apk --debug --flavor development --dart-define=APP_ENV=development
```

The Flutter build engine accepts the same settings through `--flavor` and
repeatable `--dart-define KEY=VALUE`. Never pass server secrets as Dart defines.

## Local release signing configuration

The canonical Gradle project and apps generated by `scripts/create_app.py`
never sign a release build with the debug key. Release tasks fail unless all of
the following environment variables are set and the store file points to an
existing absolute path:

- `MYAPP_RELEASE_SIGNING_ENABLED=true`
- `MYAPP_RELEASE_STORE_FILE=/absolute/path/to/your-release-key.jks`
- `MYAPP_RELEASE_STORE_PASSWORD`
- `MYAPP_RELEASE_KEY_ALIAS`
- `MYAPP_RELEASE_KEY_PASSWORD`

Set these only in a protected local shell/secret manager or a protected CI
secret store. Avoid command-line arguments, checked-in `.env` files, shell
history, screenshots, logs and source control for passwords. For an interactive
local shell, enter passwords without echo and export them only for the current
session:

```bash
export MYAPP_RELEASE_SIGNING_ENABLED=true
export MYAPP_RELEASE_STORE_FILE="$HOME/secure-keys/myapp-release.jks"
read -s MYAPP_RELEASE_STORE_PASSWORD
export MYAPP_RELEASE_STORE_PASSWORD
read -s MYAPP_RELEASE_KEY_PASSWORD
export MYAPP_RELEASE_KEY_PASSWORD
export MYAPP_RELEASE_KEY_ALIAS="your-approved-alias"
```

The project does not create a keystore or select a key alias. Obtain and protect
the release keystore through your organization's approved signing process. Do
not commit the keystore or passwords. Verify local signing configuration and
obtain explicit release approval before running:

```bash
flutter build appbundle --release
```

If signing variables are missing, blank, or point to a missing/non-absolute
keystore path, Gradle stops release artifact/signing tasks with an error.
Dependency-report and debug tasks do not require these variables. This guard
does not validate ownership, key strength, Play App Signing enrollment, or
store compliance.
